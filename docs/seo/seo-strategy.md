# トレメモ SEO戦略ドキュメント

- 作成日: 2026-07-27
- 対象サイト: https://training-memo.com
- 目的: Google検索順位向上に向けた現状分析と対策のロードマップ

## 1. 現状分析(Google Search Console 実データ, 2026-07-26確認)

### 1.1 インデックス状況

`site:training-memo.com` で検索してもヒットしないが、これは**確認方法として不正確**(Google公式も`site:`検索は網羅的・正確ではないと明言している)。Search Consoleの「ページのインデックス登録」レポートで確認した実際の内訳は以下の通り。

| 状態 | 件数 | 内訳 |
|---|---|---|
| インデックス登録済み | 1 | トップページ(`https://training-memo.com/`)のみ |
| noindexタグによる除外 | 2 | `/login`・`/register`(`config/seo.ts`で意図的に`noindex, nofollow`を設定済み。想定通りで問題なし) |
| クロール済み-インデックス未登録 | 1 | `/inquiry`(noindexタグは無いが、Google側が独自判断でインデックス見送り。お問い合わせフォームは固有コンテンツが薄く典型的なパターン) |
| サーバーエラー(5xx) | 1 | `http://training-memo.com/`(**2026/06/19時点の古い記録**。実際に確認したところ現在は`https`へ301リダイレクト→200 OKで正常。Search Console上で「修正を検証」の再クロール依頼が未実施なため記録が残っているだけ) |

**検索パフォーマンス(直近3ヶ月)**: 表示された検索クエリは実質2件のみで、いずれも「筋トレメモ」「筋トレmemo」という**ブランド名そのもの**(表示回数各1回、クリック数0)。「筋トレ 記録 アプリ」のような一般的な検索語では一度も表示されていない。

**結論**: 「インデックスされていない」のではなく、「登録は最低限されているが、ブランド名以外での露出がゼロに近い」状態。技術的なインデックス阻害要因よりも、コンテンツ量・被リンクの不足が主因と考えられる。

### 1.2 技術的な問題点

| 項目 | 現状 | 問題点 |
|---|---|---|
| レンダリング方式 | Vue3 SPA(CSR)。初期HTML(JS実行前)は全ルート共通で `<title>トレメモ</title>` 等の固定meta | ページ固有のtitle/description/構造化データは`resources/js/utils/setSeo.ts`(`@unhead/vue`の`useHead()`)で**実装済み**だが、これはJS実行後にのみ反映される。Googlebotの初回クロール(JS未実行)時点では全ページ同一のmetaしか見えないため、CSR特有のインデックス遅延・ページ差別化不足のリスクは実装済み後も残っている |
| サイトマップ (`/tr-sitemap`) | `/` `/login` `/register` `/password/forget` `/inquiry` `/recordRanking` の5ページのみ | すべて会員限定・機能ページで、検索ユーザーが読みたくなるコンテンツが皆無 |
| サイトマップ更新 | 全ページ `lastmod` が `2025-04-27` で固定 | 動的更新されておらず、鮮度シグナルが機能していない |
| meta情報 | ページごとのtitle/description/keywords/robotsは`config/seo.ts`+`setSeo.ts`で管理・実装済み | ただし上記の通りJS実行後にのみ反映されるため、Googlebotの初回評価には反映されない可能性がある |
| 構造化データ | `WebApplication`のJSON-LDをホームページに実装済み(`setSeo.ts`) | ただしこれもJS実行後にDOMへ追加される方式で、初期HTMLには含まれない(実際に`curl`で確認済み) |

### 1.3 現状のmeta情報(参考)

**初期HTML(JS実行前、全ルート共通)**:

**JS実行後(ページごとに`setSeo()`で上書きされる、Googlebotのレンダリング完了後にのみ反映)**:

## 2. 競合状況

「筋トレ 記録 アプリ」等のビッグキーワードはネイティブアプリ勢が強力に押さえている。

| 競合 | 特徴 |
|---|---|
| 筋トレMEMO | 100万ダウンロード、VALXとのコラボ実績あり。国内最大手級 |
| バーンフィット | 種目ごとに重量・回数・セット数・休憩時間を詳細記録、前回比較機能 |
| PUMP UP | 登録不要・オフライン対応、RPE/スーパーセット対応、CSV出力 |
| LIBRARY | シンプルUI、トレーニングメニュー数百種類、SNS的な応援機能 |
| マイルーティン / FitPoint | ランキング上位常連 |

加えて、上記アプリを紹介する比較・まとめ記事(smartlog, マイベスト, ハウスケアラボ等)が大量に存在し、検索結果の上位を占有している。

**含意**: 個人開発のWebアプリが「筋トレ アプリ」のようなビッグキーワードで正面から戦うのは非常に不利。ロングテールキーワードと差別化軸での戦略が必須。

## 3. 対策ロードマップ

### 3.1 すぐやるべき(無料・技術対応)

- [x] Google Search Console 登録
  - 登録済み。1.1の実データはここから取得。`/inquiry`(クロール済み-インデックス未登録)は2026-07-27時点のURL検査で既にインデックス登録済みへ移行済みを確認(追加対応不要)。`http://`(サーバーエラー記録)は現在200 OKであることを確認した上で2026-07-27に「修正を検証」を実行済み(Google側の検証完了待ち)
- [x] Vue Router の各ルートでページ固有の `<title>` / meta description / keywords / robots を動的設定する
  - `config/seo.ts` + `utils/setSeo.ts`(`@unhead/vue`の`useHead()`)で実装済み
  - **残課題**: CSRのためGooglebotの初回クロール(JS未実行)時点では反映されず、初期HTMLは全ルート共通の固定meta(1.3参照)のまま。JS実行後のレンダリング完了を待つ2次インデックス待ちになっている可能性がある → 3.3のSSR/プリレンダリング化で根本解決
- [x] 構造化データ(JSON-LD, `WebApplication`)を追加
  - ホームページの`index.html`に静的埋め込み済み(全ルート共通・初回クロール時から読める)
- [x] サイトマップに「読めるコンテンツページ」を追加し、動的に `lastmod` を更新する
  - 3.2のロングテールページ3本(`src/public/guide/`)を追加し、S3上の`sitemap.xml`に2026-07-27付で反映済み(既存6件+新規3件の計9件)。既存ページの`lastmod`固定は許容範囲としてスコープ外のまま

### 3.3 長期(アーキテクチャ変更を伴う)

現状は Vue3 SPA(CSR) + S3/CloudFront 構成。SEOを本格的に強化するなら以下を検討:

## 4. 優先順位まとめ

技術的なインデックス阻害要因(meta動的化・構造化データ・Search Console登録)、サイトマップへのコンテンツページ追加、ロングテールキーワード対応(3.2)は**2026-07-27時点で対応済み**。残る優先順位は以下の通り。

1. **最優先**: 個人開発ブログ・Zenn/Qiita/note等での言及・被リンク獲得 — 一般検索語での表示回数が実質ゼロなので、ここが最大のボトルネック
2. SSR/プリレンダリング化の検討(実装コスト大。CSRによる初回クロール時のmeta未反映を根本解決したい場合)
3. 新規ページ追加後のSearch Console実データの再確認(コンテンツページのインデックス登録状況・検索パフォーマンスの変化を追跡)
